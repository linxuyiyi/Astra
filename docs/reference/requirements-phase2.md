# Nexus v1.0.1 第二阶段：数字任务与工程能力迁移

来源：用户 2026-10-15 的直接开发要求。本文整理范围与验收契约，不是另一份实施清单。第一阶段当前未通过产品验收，先补齐基线；第二阶段只读复用分析可并行，功能实施须等待第一阶段通过。

## 目标与原则

基于 AgentScope 数字员工体系，接入自主创建、管理、跟踪、完成真实工程任务的能力：

`AgentScope 数字员工 → Task Skill/MCP → Task Service → Agent Worker Pool → OpenCode`

`任务状态事件 → AgentScope 员工唤醒 → 查询最新状态并自主跟进`

历史代码基线为 [Astra codex/astra-updates-20261010](https://github.com/linxuyiyi/Astra/tree/codex/astra-updates-20261010)。最大程度复用成熟代码、服务、页面与测试；优先迁移适配，不重新开发已有功能；新架构不保留不必要的历史兼容；保留第一阶段员工功能与交互；以真实工程能力验收，不用模拟；非必要不改 UI、接口和业务逻辑。

## 历史分析

实施前分析当前工程与历史分支，覆盖 Task Service/API/状态机、Task/Session/Workspace、OpenCode/远程连接/恢复、执行员工与 Worker、环境部署/重启/检测/日志、网关全部业务、图书馆/检索/MCP、任务总结/候选经验/审核入库及前端测试。输出直接复用、小范围适配、需要实现、不再需要四类清单。禁止跳过分析重新设计。

## Task Skill/MCP 与员工集成

- Task MCP 薄封装既有服务：创建/查询/修改/分配，启动/暂停/恢复/终止/重试，状态/进度/日志/结果，人工介入/确认/异常，交付/总结/候选经验。不复制状态机和执行逻辑。
- Task Skill 明确创建时机、任务类型/分类/验收标准、MCP 使用、异常和人工介入、持续跟进直至交付。
- 注册到 AgentScope 工具与 Skill，支持员工管理配置。员工按职责决定创建/管理任务，聊天页不提供手动创建任务按钮。
- Task Service 的完成、失败、人工介入、恢复/状态变化事件通知责任员工，优先使用原生消息与唤醒；员工收到后通过 MCP 查询当前事实。可靠投递、幂等与异常恢复，不单独建设事件前端管理页。

## 数字任务迁移

保留完整生命周期、中心筛选/表格/操作、创建/详情/编辑/执行控制、Session/Workspace、工作区/日志、人工介入/停止/恢复、变更/总结/经验。Employee 负责业务任务，Worker 负责执行。Task 关联责任员工、来源会话、类型/分类/状态、Worker 和 OpenCode Session/Workspace。保留任务中心结构与主要交互，仅调整必要字段和接口。

## Agent Worker 迁移

Worker 是 OpenCode 执行资源，不是数字员工或 SubAgent。复用旧执行员工的环境/部署与表格管理，支持新增/编辑/删除/启停/查看/监控/任务关联，使用抽屉维护。

完整保留本地/Linux 远程、SSH host/port/user/认证、工作目录/workspace root、OpenCode 路径/版本/Serve 端口、执行模型/运行配置、环境状态/连接检测/健康。一键部署、重启 Serve、测试连接、步骤/日志/结果/失败原因、异常恢复优先复用 remote_provisioning、远程执行、API 和脚本。

Pool 支持多 Worker 与并发分配，Task Service 分配资源，Worker 执行真实 OpenCode；员工与资源解耦，保留 Session、隔离与恢复，不因迁移丢运维功能。

## 网关与图书馆迁移

完整保留网关模型路由/管理、API Key/鉴权、转发/模型中转、统计/Token、配额/限流/配置和管理页面，适配员工与 Worker 调用；仅做架构接线和必要适配。

完整保留图书馆资源、检索、MCP、总结/经验候选、审核/发布/入库、前端交互；员工使用所配置知识和记忆，打通任务经验沉淀；不无关重构。

## 前端

采用已确认五页面原型：

- 数字员工保留对话，不设创建任务按钮；右侧“任务/职责/能力/记忆”，任务随真实状态更新。
- 团队保留 @员工、消息和附件；右侧 Tab 展示关联任务与员工信息。
- 数字任务复用旧任务中心/详情，仅调整新关系。
- Worker 复用旧执行员工表格、抽屉和完整环境运维。
- 网关/图书馆保留页面与完整交互，只适配导航和接口。

统一 Element Plus，不添加演示文字、架构解释或冗余提示。原型中的模拟数据不得成为实现。

## 实施约束

Codex 分析、设计、拆解、审查与验收，OpenCode 实际编码，优先用户指定 DeepSeek V4.1 Flash；实际调用名 `deepseek/deepseek-flash` 已由用户确认，避免无效模型 ID。

按历史差异分析、数据关系/迁移契约、Task/MCP/Skill、AgentScope 注册/配置/真实调用、Worker/运维/Pool、网关/图书馆、页面/事件、真实端到端顺序推进。独立开发分支，不改 master；分模块开发/测试/验收，重大架构冲突或取舍确认；不扩大范围、不顺带重构；第三阶段自主多员工职责协作不作为第二阶段前置。

## 最终验收与交付

至少一条真实工程闭环：人类提出需求 → 员工 Skill/MCP 自主创建 Task → Service 分配 Worker → OpenCode 实际工程工作 → 员工查询/修改/控制/跟踪 → 异常或完成事件唤醒 → 员工继续处理/必要时人工介入 → 验证交付/经验沉淀 → 中心/Worker/员工对话关联一致。另验证网关/图书馆原功能、多任务并发、Worker 故障、Session 恢复、真实部署运维。

交付历史复用清单、迁移模块与代码说明、Skill/MCP 与 AgentScope 集成结果、完整功能/端到端报告、遗留问题与风险。核心是以最小改造将成熟工程能力接入员工体系，不重新开发一套 Nexus。
