# 第二轮验收

基线为 `linxuyiyi/Astra` 的 `v1.5.0` 提交 `7d8089ad6`。Nexus 与 Agent Service 使用同版本代码，Nexus 数据库以 Alembic `0001_init` 从空库建立。

## 接口与原生能力

- 私聊发送和群消息都携带 `client_id`。同一条消息重试复用该值。私聊从原生 Session 的消息日志确认 `Msg.id` 已持久化，Agent Service 在原生运行入口拒绝重复执行。
- 群补送使用 AgentScope 的 Session 锁、`SessionState.context` 与原生消息日志。应用层仅提供一个内部历史追加接口，将有界批次写入原生存储。
- 附件 PUT 接收原始字节，并指定私聊或群组。回复引用保存附件 ID 和展示信息。恢复私聊时返回 `missing_attachment_ids`，已失效引用下载返回 404。
- 私聊 `GET .../stream` 透传原生事件，调用者通过 `after` 传入 Redis 回放游标。AgentScope 运行结束由原生 `REPLY_END` 表达。

## 回归范围

- Nexus API 验证私聊超时重试、Nexus 确认写入失败、Session 重绑、跨 UID 隔离、缺失文件、群多批补送和回复确认丢失、Skill/MCP 配置变更及撤权。
- Agent Service 实际运行 AgentScope 2.0.10 和原生 SQL 存储，验证历史写入中途断开后的修复、原生模型输入顺序、Workspace 文件读取及服务重启后的工具去重。模型由确定性测试替身提供。
- MySQL 8.0.36 空库初始化和群并发用例通过，包括远程回收期间可以获取群行锁，以及回收失败后的绑定保护和重试。AgentScope 原生 SQL 与消息链路用例也在独立 MySQL 库执行。
- Chromium 检查群附件上传、历史刷新、下载哈希和群外拒绝，以及私聊原生回复、工具调用展示、历史刷新和跨 UID 拒绝。拦截第一次成功响应并返回 503 后，重试保留同一 client_id，最终只有一条用户消息、一条回复及一次工具执行。
- Nexus 全量测试 827 通过、22 跳过。Agent Service 24 通过、1 跳过。单独启用 MySQL 8.0.36 后，群并发 4 项、AgentScope SQL 与消息链路 10 项均通过。真实 MySQL、Redis 和 AgentScope 运行两名员工的群讨论，各自按序收到 130 条历史。
- 聊天岛 17 项、Web 72 项测试通过，类型检查与生产构建通过。

## 边界

- 生产模型网关、公司身份环境和实际发布未执行。
- 原生用户消息已落盘而执行进程随即退出时，重复请求会确认已投递的消息。原执行可能没有回复，避免自动重放可能已执行的工具。
- 群讨论的进程级中断会将当轮讨论标为中断。后续讨论从已有接收游标补齐历史。
