## 决策

1. **成功判定放在数据面**：流式响应只有同时满足「媒体类型为 `text/event-stream`、至少一帧实际内容、出现 `[DONE]` 或 `finish_reason`」才算成功；只有结束标记、空内容、错误媒体类型、未到终止标记就 EOF 分别记为 `STREAM_EMPTY`、`UPSTREAM_PROTOCOL_ERROR`、`STREAM_INCOMPLETE`，计入错误与节点被动失败，不改变已发送给客户端的字节。
2. **额度准入在调度之前**：Key 小时/日额度读取运行态分桶计数，达到上限直接 429（`KEY_QUOTA_EXCEEDED`），不取节点租约、不发上游请求。节点额度只由 `STOP` 阻断；`ALERT`/`RECORD` 在任意比例都不参与权重，未知用量不计为 0，也不阻断。
3. **模型别名在流式分帧层回写**：按行增量解析 `data:` JSON，只替换 `model` 字段；非 JSON 行、`[DONE]`、心跳原样透传。不缓存整流，不改变重试范围（仅在未发送时重试）。
4. **探测以轮次为事实**：新增轮次表，一次操作一条记录（来源、首模型、作用域、耗时、步骤、用量）；提交与幂等以轮次键 + 租约 token 做条件写入；健康运行事实只由轮次的最终结论推进，晚到投影按轮次序号丢弃。
5. **配置关系读模型**：服务端返回池成员、模型、关联路由与候选/阻断原因；启用路由必须有静态候选；移动/删除最后成员或目标模型前必须先停用路由或补足候选。

## 被舍弃方案

- 在客户端判定流是否成功（客户端版本不可控，无法约束调用日志与熔断）。
- 对 ALERT/RECORD 继续用降权表达告警（与「不因额度降权」冲突，告警改为运行事件与页面状态）。
- 把旧步骤记录按时间窗口猜测归组为轮次（会伪造历史事实）。
