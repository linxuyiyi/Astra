## 三、技术架构

采用以下总体方向：

```text
Nexus Vue3 + Element Plus
          │
     Nexus Backend
          │
  AgentScope Agent Service
          │
  Agent / Session / Memory
  Tools / Skills / Knowledge
  Multi-Agent Communication
          │
      Model Service
```

### 架构要求

1. AgentScope 优先使用官方 Agent Service、SDK、API 和扩展机制。
2. AgentScope 独立部署，Nexus 通过稳定接口集成。
3. 不直接复制、Fork 或修改 AgentScope 核心源码。
4. 员工身份、Agent、Session、Memory 等优先复用原生机制。
5. Nexus 仅保存必要的业务扩展和关联数据。
6. 避免建立两套 Agent 管理、会话管理和记忆系统。
7. 模型配置统一由 AgentScope 管理，Nexus 不提供模型配置页面。
8. 前端使用 Vue3 + Element Plus；后端使用 Python，具体框架优先选择能够最简单集成现有服务的方案。
9. 优先采用模块化单体业务架构，不引入无必要的微服务和复杂基础设施。

**必须先研究当前 AgentScope 官方源码、实际 API 和运行约束，再确认最终集成方式。**

尤其确认 Agent Service、Agent 创建、Session、Memory、Skill、Knowledge、多 Agent 通信的真实能力。不能根据框架名称或示例臆测 API。

## 四、功能范围

### 0. AgentScope 配置与部署

- 确定并固定可用的 AgentScope 2.0 版本。
- 完成独立服务部署、模型接入、持久化配置。
- 提供环境变量模板、启动脚本和部署说明。
- 支持服务启动、停止、健康检查。
- Nexus 可正常连接 AgentScope。
- 员工、会话数据在服务重启后能够恢复。

优先复用官方部署方案，不重写 Agent Service。

### 1. 员工管理

**一个数字员工就是一个独立的岗位责任主体，不再设置岗位模板。**

按照原型实现：

- 员工列表与搜索。
- 创建、编辑、删除员工。
- 启用、禁用员工。
- 员工身份、名称、职责、工作指令配置。
- Knowledge、Skill、Tools 的关联选择。
- 员工详情及配置展示。

要求：

- 每个数字员工对应独立 AgentScope Agent。
- 创建、修改、删除必须真实调用 AgentScope。
- Skill 优先从 AgentScope 已有资源目录选择，不通过自由输入重复定义。
- Knowledge、Tools 同样优先复用 AgentScope 的资源管理机制。
- 如 AgentScope 不提供完整选择接口，先调查真实资源机制，再做最小适配。
- 禁用员工后不能继续触发新的 Agent 运行。
- 保证前后端数据一致，不能只修改页面状态。

### 2. 数字员工对话

按照最终原型实现：

- 选择数字员工交流。
- 多轮对话、流式输出。
- 在聊天窗口内新建对话。
- 历史对话查看、切换和恢复。
- 支持文件、图片上传。
- 支持拖拽、粘贴截图。
- 发送前预览、移除附件。
- 消息中的图片预览、文件查看和下载。
- 右侧展示员工职责、能力及记忆信息。
- 对话页面不提供员工编辑功能。

**会话设计：**

当前没有登录系统：

- 浏览器生成并保存匿名 UUID。
- 不同浏览器身份分别维护自己的对话。
- 同一员工可以有多个 Conversation。
- Conversation 与 AgentScope Session 建立稳定关联。
- 服务端负责对话、消息和附件持久化。
- 浏览器仅保存临时身份及必要 UI 状态。
- 后续支持绑定真实人员 UID。

匿名 UUID 不是可信身份认证凭据。当前版本仅用于受控验证环境，不得将其作为正式生产环境的数据访问安全保障。

**附件处理：**

- 真实完成上传、保存和下载。
- 优先复用 AgentScope 的多模态消息能力。
- 图片支持按模型实际能力进行理解。
- 文本、代码、日志等文件支持真实内容读取。
- 其他文件类型根据实际能力处理，不支持时明确提示。
- 不允许模型在未读取附件时声称已经分析。

### 3. 团队交流

这是 v1.0.1 的重点能力。

按照原型实现：

- 创建和编辑团队讨论。
- 添加、移除参与员工。
- 多名数字员工参与同一讨论。
- 人类通过 @ 指定数字员工。
- 数字员工可以主动联系其他数字员工。
- 员工之间能够进行真实消息交互。
- 多员工交流过程实时展示。
- 消息历史持久化。
- 支持文件、图片及消息附件。

**核心架构约束：**

团队中的数字员工是长期存在、身份平等、职责独立的 Agent。

不能把员工 B 实现成员工 A 临时创建的 SubAgent。

优先复用 AgentScope 原生的 Team、消息传递、协作和会话能力，但不能强行将 Leader-Worker 工作流等同于平等员工交流。

需要实现的实际场景：

1. 人类 @防线运营员工，询问自动化失败情况。
2. 防线运营员工分析后，判断需要自动化工程师协助。
3. 防线运营员工主动联系自动化工程师。
4. 自动化工程师基于自身职责和上下文回复。
5. 需要时进一步联系测试工具工程师。
6. 交流过程在同一团队讨论中完整呈现。

员工的交流应由真实 Agent 推理和工具调用驱动。

禁止通过硬编码关键词、预设回复、固定轮流发言模拟多 Agent 协作。

增加必要的消息去重、轮次限制和循环终止机制，避免无限相互调用，但不要引入复杂的协作编排系统。

## 八、验收标准

最终必须真实验证：

1. Nexus 与 AgentScope 能够正常部署运行。
2. 员工创建后，AgentScope 中存在真实 Agent。
3. 修改员工职责后，新对话使用更新后的配置。
4. 禁用、删除员工真实生效。
5. 单员工支持真实多轮流式对话。
6. 新建与切换历史对话正常，刷新和重启后可以恢复。
7. 不同匿名浏览器身份的会话保持隔离。
8. 文件、截图可以上传、查看，并在支持的范围内被 Agent 实际读取。
9. 创建包含三名独立员工的团队讨论。
10. 员工 A 能主动联系员工 B，并获取真实回复。
11. 多员工消息正确展示，不串身份、不无限循环。
12. 不存在模拟 AI 回复、假接口和仅前端生效的功能。

涉及数据库、消息、文件或 AgentScope 服务的操作，必须有真实执行及验证证据。

不能完成的功能明确记录限制与原因，禁止用假实现替代。
