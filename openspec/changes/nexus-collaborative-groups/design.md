## Context
现状没有账号密码认证：X-Owner-Id 与可写 Cookie 被当身份；读群会自动登记人类。员工仅在 @ 时触发，循环调用只等待受理，不等待回复。历史来自跨 Session 合并，人类行均标为“我”。

## Goals / Non-Goals
建立可信多人群、统一公开日志与有限有序讨论。不增加 Agent 内部流程、Leader、TeamPipeline 或第二套任务状态机。

## Decisions
- 身份使用密码 scrypt 哈希与随机会话 token（数据库仅存摘要、过期可撤销、HttpOnly/SameSite）；停用自报 UID。首个账号为平台管理员，后续账号默认仅聊天权限，操作权限由管理员授权。内部回调使用服务间密钥，浏览器无法调用。
- 统一 channel_members 的 member_type/member_id，员工 Session 仍在关系上绑定；旧无可信身份的群不猜测归属，通过显式管理员认领恢复。新 Alembic revision 扩展，绝不改 init。
- Nexus 只保存群组公开消息作为协作事实源（本需求明确要求）；AgentScope 继续独占 Agent、Session、内部记忆与执行状态。Session 中输入是公开日志的派生上下文，不用于拼凑群历史。原生 Msg 保留格式与附件。
- 群序号由数据库原子递增分配；请求幂等键按群+人类约束。SSE 使用有序持久传输事件及游标回放，最终正文在群消息日志；退出/移除后持续鉴权。
- 讨论持久化状态和发起者；数据库租约隔离每群运行，多进程可争抢但仅一人执行。每条人类新消息终止旧 generation；完成持久化后才允许后者发言。进程崩溃时租约过期，残留讨论中断，不猜测重放有副作用的工具。
- 规则路由：显式提及保持文本顺序、岗位关键词匹配、招呼选一人；多人之间陈述与 @人类不触发推理。继续条件为明确对同事的问题，限制每人最多两次、最多六轮、总时长与输出 Token。每轮通过 AgentScope 官方输入及事件流，不生成员工台词。
- Agent Service 按服务端解析的群讨论上下文限制工具；未获实际操作权限者移除所有有副作用工具。Task MCP 再检查群成员、讨论发起人、岗位技能及当前 generation；权限信息不信任提示词。

## Risks / Trade-offs
- 规则路由覆盖不了全部语义：只在有岗位相关性或明确请求时触发，避免每条人类消息消耗模型；不保证所有隐含请求自动识别。
- 上游故障：公开消息先落库，讨论显示失败；不虚报模型回答。Token 限额基于受控模型 max_tokens 与实际 usage 双重限制。
- 部署需一起更新 API、Agent Service 与前端。旧自报身份不能回填为真实账号；管理员认领群后显式重新邀请人类。
