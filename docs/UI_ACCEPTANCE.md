| 视口 | 员工管理 | 私聊与团队交流 |
| --- | --- | --- |
| 大屏 | 列表与档案两列；原型 `minmax(550px,1fr) 345px`，间隔 16px | 三列；原型 `245px minmax(380px,1fr) 295px`，间隔 15px |

## 员工管理

### 列表与档案

页面标题右侧为「创建数字员工」。列表顶部为「员工列表」、筛选后的数量和「搜索员工 / 职责」输入框。搜索匹配名称、责任领域、职责说明。

| 列 | 展示与交互 |
| --- | --- |
| 数字员工 | 头像、名称、员工 ID |
| 职责 | 责任领域和截断的职责摘要；全文在档案中查看 |
| 技能 | 前两项技能中文名称，剩余数量以 `+N` 表示；保留 ID 的补充信息 |
| 状态 | 启用/禁用开关，操作有加载和失败反馈 |
| 操作 | 对话、编辑、删除；点击操作不能意外改变选中状态或重复触发 |

点击行选中员工并更新右侧档案。档案包括头像、名称、领域、启用状态、职责范围、知识资源、技能、工具、员工 ID，以及「与 X 交流」按钮。档案的编辑按钮打开同一员工抽屉。

搜索无结果显示「没有找到符合条件的员工」。尚无员工时，展示创建首位员工的空态和明确创建入口，不显示失效操作。

### 创建与编辑抽屉

右侧抽屉宽度基准为 `min(610px,100%)`；头尾固定、中部滚动。创建和编辑共用表单；编辑打开时读取真实配置。

| 字段 | 原型值与约束 | 工程化映射 |
| --- | --- | --- |
| 员工名称 | 必填，最多 24 字符 | 去除首尾空白，同名忽略大小写禁止；服务端最终校验 |
| 责任领域 | 必填，最多 42 字符 | 同领域忽略大小写禁止；服务端最终校验 |
| 员工形象 | 五个 emoji 选项 | 保留工程师、分析师、技术专家、数字员工、工程师 B |
| 职责说明 | 必填，多行 | 明确工作范围和交付职责 |
| 工作指令 | 必填，多行 | 创建时提供原型默认指令；不能替代真实 Agent 配置 |
| 知识 | 原型多行文本 | 按真实 AgentScope 资源机制关联选择；只有官方机制确需文本引用时做最小适配 |
| 技能 | 已注册目录多选 | 支持名称/ID 搜索、已选数量、可移除标签；不提供自由定义技能输入框 |
| 工具 | 原型多行文本 | 按真实工具目录关联选择；展示名称及必要的标识 |
| 启用此员工 | 底部开关，创建默认开启 | 由服务端持久化并限制新的 Agent 运行 |

原型创建默认工作指令为「收到消息后先判断能否直接回答；信息不足时追问；需要其他员工帮助时联系相应员工；不得编造真实执行结果。」原型默认工具为 `search_knowledge`、`contact_employee`；正式版本只能选择真实存在、已注册且可用的工具，不创建同名假工具。

表单缺失必填项、名称重复、领域重复时显示对应字段错误，保留用户输入。保存期间防重复提交；只有后端和 AgentScope 操作成功后关闭抽屉、更新列表并提示成功。取消、关闭、遮罩和 Escape 行为一致；有未保存修改时采用一致的防误关处理。

页面不增加岗位模板、模型配置或其他复杂设置。

### 删除与历史可达性

删除先展示危险确认：「删除后将不再显示该员工，历史对话仍保留。」确认成功后，员工退出活动列表和团队可选成员，不能触发新的运行。AgentScope 的删除必须真实生效，不能只隐藏前端行。

原型只保留历史数据，没有查看已删除员工私聊的入口。建议最小业务扩展为：Nexus 员工关联记录采用软删除，保留显示历史所需的身份快照和 Session 关联；对应 AgentScope Agent 按正式契约删除。数字员工页面在现有左侧列表内提供「归档历史」入口或列表分组，查看已删除员工的历史，明确标注「已删除」，禁止新对话与发送。团队历史仍显示当时作者身份。此处理不增加页面、不允许恢复或继续运行已删除 Agent。

风险：AgentScope 删除 Agent 后是否保留 Session、消息和关联文件，需要真实接口验证。若官方删除会级联删除历史，必须先在 OpenSpec 中明确可实现的历史保留边界；不能依赖前端数组未清空宣称历史可查。

## 数字员工

### 员工选择与对话头部

左侧为「我的数字员工」、数量、员工列表。每项展示头像、名称、领域和启用状态；禁用员工仍可查看历史。对话头部展示员工头像、「名称 · 责任领域」、职责摘要、当前对话下拉和「新对话」按钮。此页面没有员工编辑入口。

同一浏览器身份、同一员工可以拥有多个 Conversation；Conversation 与 AgentScope Session 稳定关联。历史下拉显示名称、创建日期、消息数，当前项高亮。新对话初始名为「新对话」；首条文本用前 20 字符生成标题，纯附件对话使用首个文件名。标题过长省略，完整内容仍可查看。

浏览器保存匿名 UUID 和必要 UI 状态，服务端持久化 Conversation、消息、附件及关联信息。匿名 UUID 仅用于受控验证环境的身份划分，不等同可信认证。不同匿名身份的历史列表、消息和附件必须按同一身份范围访问和隔离。

### 消息与输入

- 用户消息右侧、浅绿气泡；员工消息左侧、柔和灰绿气泡。
- 作者、时间、头像和附件身份一致；历史消息使用稳定作者标识及必要的身份快照。
- 支持真实多轮和流式输出，展示执行中、失败及可重试状态；真实内容来自后端事件。
- Enter 发送、Shift+Enter 换行；中文输入法组合期间 Enter 不发送。
- 文本或附件任一非空才可发送；上传未完成时不能发送不完整附件引用。
- 保留「你的职责」「你的能力」「技术咨询」三个快捷问题；原型点击直接发送，工程实现应走与普通发送相同的真实请求路径。
- 切员工、切历史或新建对话时，文本与附件草稿按明确的 conversation 归属保存或清空，不能把旧草稿带入新会话。
- 禁用或已删除员工禁止新的运行；输入、快捷发送、附件选择、拖放、粘贴等入口行为一致，历史可读。
- 流式事件切换会话后只能更新原会话，不能写入当前显示的另一会话。

首次打开空对话显示员工头像和「与 X 开始交流」。无员工显示「尚未创建员工」「请前往员工管理」及管理入口；清空旧头部、资料和发送状态。历史加载失败显示错误和重试入口，不能伪装成新对话空态。

### 右侧资料

| 标签 | 内容 |
| --- | --- |
| 职责 | 头像、名称、领域、职责范围、工作指令 |
| 能力 | Knowledge、Skill、Tools 的真实关联资源；无配置时明确展示空态 |
| 记忆 | 真实可读取的记忆信息；无长期记忆时显示「暂无长期记忆」，以及对话消息数量、员工 ID |

原型记忆页只有占位和私聊消息汇总，不能把消息数量冒充长期记忆。若当前官方服务不提供可读取的记忆接口，保留准确空态或实际能力限制，不编造记忆内容。

## 团队交流

### 频道、消息与参与者

左侧为「团队频道」、数量和频道列表；每项显示名称、数字员工数、讨论目标摘要。主区域头部显示 `# 讨论名称`、目标、员工数量和设置按钮。右侧为「讨论参与者」与「调整成员」，首先显示当前人类发起人，再显示员工头像、名称、领域、启用/禁用状态。

团队消息与私聊共用气泡、流式内容、附件和错误反馈。所有员工都是长期独立、身份平等的 Agent，不能在 UI 中把被联系员工标成临时 SubAgent。真实主动联系、目标员工回复与后续协作过程在当前讨论中按身份展示。

无频道时显示「创建一个团队讨论」和创建入口，清空旧目标、成员、快捷项和输入状态。频道成员调整后，列表、成员数量、mention 候选和运行权限同步更新。

### 创建和编辑讨论

标题右侧「新建讨论」打开对话框；设置和「调整成员」打开同一编辑对话框。宽度基准 510px，内容较长时滚动。

| 字段 | 约束 |
| --- | --- |
| 讨论名称 | 必填，最多 32 字符 |
| 讨论目标 | 必填，多行 |
| 参与的数字员工 | 至少一名；显示头像、名称、领域及可用状态 |

创建默认选择已启用员工。已有讨论可以显示其禁用成员，但禁用成员不能被触发运行；禁止选择已删除员工。成功创建后新讨论放到列表前部并选中。保存失败保留内容并给出可操作错误。当前范围没有频道删除入口，不擅自添加菜单。

### @ 与员工主动联系

在输入尾部键入 `@` 时显示当前频道已启用员工候选；支持姓名筛选、键盘选择和 Escape 关闭。点击快捷 `@员工` 或候选插入显示文本，同时保留稳定 employee ID 的 mention 引用。候选包含头像、名称和领域。

原型快捷区最多显示前三名已启用成员，其余仍可从候选选择。「分析协同」只填入讨论示例，不自动发送。普通未 @ 消息可以持久化，不应无条件触发所有员工。人类 @ 的实际目标以结构化引用为准，避免按姓名片段误匹配、改名或重名错误。

员工主动联系另一名员工必须由真实推理和工具调用驱动。界面消费服务端消息与状态，不根据关键词安排下一位员工，不固定轮流发言。重复事件只展示一次，达到轮次或循环限制时清楚结束当前交流，历史保留。

## 私聊和团队共用附件

### 输入、预览与限制

| 项目 | 规格 |
| --- | --- |
| 入口 | 点击附件按钮、多文件选择、拖放到聊天区、粘贴截图/文件 |
| 单条数量 | 最多 6 个附件 |
| 单文件大小 | 最大 20 MiB，即 `20 * 1024 * 1024` 字节；提示文案可沿用 20 MB |
| 空文件 | 拒绝，并显示原因 |
| 草稿 | 图片缩略图或文件图标、文件名、大小、移除按钮 |
| 发送 | 支持只有附件；上传完成后以服务端附件 ID 发送 |
| 状态 | 上传中、上传失败、重试、移除；错误不丢失其他已上传附件 |

数量和大小限制在选择、拖放、粘贴和服务端一致执行。并发选择或粘贴不能突破数量限制。上传异步完成时，附件只进入其原草稿，不得落入已切换的员工或频道。移除和放弃的上传需按服务端策略清理，不能长期积累孤立文件。

### 消息中的查看和下载

图片卡片使用约 88×68px 缩略图；文件卡片显示图标、名称、大小和查看/下载操作。纯附件消息不显示空气泡。

图片点击打开深色全屏预览，顶部显示名称、「保存」「关闭」；支持 Escape 和遮罩关闭。文本、代码、日志文件提供真实内容查看和下载；其他类型按实际支持情况提供下载或准确提示。内容丢失或无权访问时明确报错，不能显示空白预览当作成功。

文件由服务端持久化并受同一匿名身份及会话范围约束，刷新和服务重启后仍可访问。原型 IndexedDB 和 localStorage 仅是本地演示方案，不进入正式附件存储。

图片理解使用模型真实支持的多模态输入；文本、代码、日志须真实读取内容后再供 Agent 分析。不支持解析的类型明确提示，禁止仅根据文件名生成“已经分析”的回复。

## 最小共享组件边界

| 组件 | 责任 |
| --- | --- |
| `NexusLayout` | 顶部品牌、主题、内容容器、三个底部导航 |
| `EmployeeManagementView` | 员工列表、搜索、选中档案、管理操作 |
| `EmployeeChatView` | 员工选择、历史对话、资料标签及归档历史入口 |
| `TeamDiscussionView` | 频道选择、成员展示、讨论管理、团队事件 |
| `EmployeeEditorDrawer` | 创建/编辑共用表单和真实资源选择 |
| `DiscussionEditorDialog` | 创建/编辑讨论及成员选择 |
| `ConversationPanel` | 可定制头部、消息展示、消息滚动、流式与失败状态 |
| `MessageComposer` | 文本、快捷项、附件草稿、发送键盘行为、可选 mention 模式 |
| `MessageAttachment` | 消息附件卡片、预览、内容查看、下载 |

优先使用 Element Plus 的 Table、Drawer、Form、Select、Tabs、Dialog、CheckboxGroup、ImageViewer 等已有能力。员工档案和简单列表区域可先保留在对应页面内，不为每个样式块拆组件，不建立通用表单解释器。共享附件处理与消息订阅，避免私聊和群聊各实现一套。

前端状态只保存选中 ID、临时草稿、弹层和必要 UI 状态；员工配置、Conversation、Session、消息和运行结果以服务端及 AgentScope 的实际接口为准。

## 原型 mock 明确排除

| 原型实现 | 正式版本要求 |
| --- | --- |
| `defaults()` 中三位员工、两个频道及预置消息 | 不作为生产初始化数据自动注入；测试数据须明确隔离 |
| `privateReply()`、`groupReply()` | 删除关键词回复，使用真实 Agent 输出 |
| `sendGroup()` 的姓名包含匹配、最多三人及固定协作链 | 使用结构化 mention 与真实联系工具；循环限制由正式契约定义 |
| localStorage 保存员工、消息、频道 | 服务端持久化；浏览器只保存匿名身份与必要 UI 状态 |
| IndexedDB 保存附件 | 真实上传、存储、内容查看和下载 |
| 仅修改 `enabled` 或数组删除员工 | 后端持久化并真实调用 AgentScope |
| 硬编码技能目录 | 真实注册资源目录或经调查确认的最小适配 |
| 消息“模拟”标签、原型重置按钮 | 正常产品移除 |
| “当前无法执行”“当前是交互原型”等固定回答 | 由真实能力、工具结果和错误产生准确反馈 |
| 空白系统消息与过滤特定演示文字 | 不为演示遗留内容建立兼容逻辑 |

## UI 验收情景

下表记录可观察行为，不维护任务进度；实际验证证据归入 OpenSpec 验证及测试报告。

| 情景 | 应观察到的结果 |
| --- | --- |
| 三页导航、大屏和窄屏 | 原型主题与布局关系保留；无第四页；窄屏可切员工/频道、查看资料并发送 |
| 员工创建、编辑、重复校验 | 后端成功后列表和档案同步；失败保留表单；真实 Agent 配置一致 |
| 员工禁用 | 所有发送与上传触发入口一致受限；已有历史可读；新的运行在服务端被拒绝 |
| 员工删除 | 活动入口消失、不能运行；归档历史可在现有页面到达；历史身份不串改 |
| 同员工多对话与匿名身份切换 | 历史、消息、附件隔离；刷新及重启恢复正确 Session；无草稿或流事件串会话 |
| 单员工流式消息 | 逐步显示真实输出；网络失败可见且不伪造完成；重连和重试不重复展示 |
| 创建、编辑团队与调整成员 | 列表、数量、成员、候选同步；禁用/删除员工无法被触发 |
| 人类 @ 与员工主动联系 | 指定员工真实响应；主动联系目标身份独立；同一讨论呈现过程，无关键词假协作 |
| 选择、拖放、粘贴附件 | 三入口一致执行 6 个/20 MiB/空文件限制；草稿可预览和移除；纯附件可发送 |
| 附件持久化和理解 | 刷新/重启后可查看下载；支持内容被真实读取；不支持类型给出准确提示 |
| 空态、加载、错误 | 无旧数据残留；加载不冒充空态；错误提供对应恢复入口 |
| 键盘与可访问性 | 输入法 Enter 不误发送；弹层焦点正确；技能、历史与 mention 可键盘操作 |
