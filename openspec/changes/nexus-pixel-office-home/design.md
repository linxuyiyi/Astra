## Context

当前 `/` 为 NebulaHomeView；`/api/v1/nebula/snapshot`、nebulaStore 提供员工计数、Worker 健康/占用及 SSE 失效刷新。现有员工详情按绑定筛选 Worker，任务预览受全局截断限制，不能直接作为办公室工作台完整来源。V5 是用户提供的自包含 HTML，有完整家具与六款机器人的 PNG 素材。

## Goals / Non-Goals

实现真实可操作的办公室入口。不更改调度、生命周期、模型、权限及 schema；不创建演示员工，不复制 AgentScope Session。其他页面保留。

## Decisions

- 提取 V5 原始 PNG 素材并记录来源，复用其场景绘制方向；Vue 管理可访问的工位按钮和工作台，Canvas 只绘制装饰。选择员工不放大或以员工为中心平移；打开工作台只适配可用区域，手机以底部工作台覆盖部分办公室，保持原视角，避免十二人被压缩为微缩图。
- 新增 `GET /api/v1/nebula/employees/{id}/office`，复用现有目录、状态 DTO、任务归属规则；Worker 和待处理各 20 条分页，Worker 带当前员工任务摘要。SQL 对该员工查询，不依赖全局 400 条预览。Worker 当前任务关联优先；已有绑定只代表现行调度配置，未执行本员工任务且正在执行其他任务的 Worker 不列为本员工资源。
- 员工计数沿用聚合事实；任务归属沿用 responsible_employee_id 优先和现有绑定补全。共享未绑定 Worker 通过实际 Task.employee_id 关联，不增加持久化归属。健康/占用沿用后端投影。等待原因沿用现有中文映射。
- 私聊入口按员工 ID 进入现有聊天；办公室不返回其他用户会话引用。任务入口进入已有详情/工作区，Worker 入口进入已有配置。
- 仅展示真实目录，每页最多十二位；桌面按数量适配：四人为2×2、九人为3×3、十二人为4×3；窄屏最多三列，末排居中。默认视角限制人物放大倍数，姓名状态独立保持可读大小；多排不重复显示悬浮气泡，避免遮挡，完成反馈仍显示于姓名牌且不覆盖人工异常状态。共享常量统一分页、选人和路由定位；角色沿用 avatar identity capability 的保存 ID，不更改业务岗位。
- 工作台响应单独带员工 ID 与快照时间；AbortController 和请求序号防止切换竞态，刷新失败保留上次数据并明确标识。复用首页 store 的 15 秒轮询和 SSE 失效，不增加全局轮询。
- Worker 使用语义单列列表而非表格，符合用户明确要求；因此不套 el-table。分页沿用 Element Plus。

## Risks / Trade-offs

- 数字员工状态表示平台任务工作概况，不表示 AgentScope 正在推理；标识仅按确认的任务计数，未知/降级不播放工作动画。
- 当前绑定是既有调度约束，页面不会把空闲共享池全部算作员工资源；无关系显示空态及共享资源入口。
- 聚合两套数据库访问非原子事务，复用现有只读边界并标记更新时间。未对公司 MySQL/真实模型执行做生产验收。

## Migration Plan

无数据库迁移。构建前端并启动包含新接口的统一服务；回滚本变更即可恢复星系首页。

2026-10-30 补充仅调整前端比例与交互；回滚该补充提交可恢复原六人分页/聚焦，不移除已有办公室接口。
