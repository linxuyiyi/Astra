# console-data-refresh Specification

## Purpose

明确管理台各页面进入、筛选、手动刷新和业务操作后的数据读取边界，避免无人操作时持续轮询或因业务事件重读快照，同时保留平台助手回复、任务工作区执行流与原有人工介入能力。

## Requirements

### Requirement: 管理台按需加载

管理台 SHALL 在进入页面、用户刷新、筛选交互及业务操作成功后按需读取数据，MUST NOT 在用户闲置时定时重读数据，或因业务事件、连接恢复及页面重新可见而自动重读。此边界不包含助手回复和 OpenCode 工作区执行流。

#### Scenario: 页面闲置与切回前台
- **WHEN** 用户停留在首页、任务或员工页、图书馆、网关，或将页面切回前台
- **THEN** 页面保留已加载快照，不新增后台数据刷新请求

#### Scenario: 业务事件到达
- **WHEN** 后端产生任务或员工事件
- **THEN** 管理台不因该事件重读列表、任务详情、工作区绑定或 Git 信息

#### Scenario: 执行与助手交互
- **WHEN** 用户在 OpenCode 工作区执行任务、回答权限问题或向平台助手发送消息
- **THEN** 对应执行流和回复仍可正常工作，不受管理台自动刷新关闭影响

### Requirement: 手动刷新可用

首页、员工和任务列表、任务详情、待处理、图书馆及网关 SHALL 提供手动刷新；核心全局快照及任务详情刷新进行中 MUST NOT 因重复点击产生重复批次。用户操作完成后 SHALL 继续呈现操作结果。

#### Scenario: 手动更新与失败重试
- **WHEN** 用户点击刷新或加载失败后的重试
- **THEN** 页面获取当前数据，成功后展示新快照，失败时明确提示并允许再次尝试

#### Scenario: 刷新进行中
- **WHEN** 全局快照或任务详情正在刷新，用户再次触发刷新
- **THEN** 复用当前请求，不叠加相同刷新批次

#### Scenario: 操作成功
- **WHEN** 用户启动、停止、重试或确认任务，或保存管理配置
- **THEN** 页面更新该操作结果，任务执行仍由原有后端生命周期管理
