## Context

经验总结由现有 Map/Reduce 复盘器直接调用网关模型执行，不是员工调用的 AgentScope Skill。Google Research Harness² 的参考版本为 `1cfe254e8d25b15f37048c3730134686abe60335`，重点参考 `harness2/core/prompts.py::experience` 和 `library.py`。只借鉴决策原则，不复制其执行框架。

## Goals / Non-Goals

改进候选质量、减少拆分和重复，实际对照旧/新提示词的行为。保持独立后台复盘、人工审核和现有凭据边界，不自动编辑员工 Skill、不新增运行编排或 Agent 存储。

## Decisions

- 调整真正生效的 Map/Reduce 提示词：观察记录与可迁移经验分开；通常一条完整经验，零条合法。保留现有可配置上限作为预算，不把 3 换成另一个固定配额。
- 以适用条件、实际改变、行为差异、验证与限制表达一条经验。合并方法、测试矩阵和交付检查；未验证 Skill 实际加载或多个因素同时改变时不归因为该 Skill 生效。
- 只加载该任务实际 read 使用记录绑定的 candidate/published 内容作参照；按现有 Task/Session 来源限定、限制数量与字符预算，先脱敏。不查询任意私有空间，不引入向量库或全局记忆。
- 归纳结果超过一条时做最终语义合并，即使未达到数量上限；有已读参照时单条也比较，补常规测试只扩充原方法证据；已有经验的相同方法只记录复用，独立新约束/反例才允许形成新候选。
- 用相同真实观察输入、同一网关模型、旧/新提示词分别重复至少 5 次；另用未参与调词的正负场景验证。评分与输入分离，不把期望答案送进模型；不修改历史候选来伪造改善。

## Risks / Trade-offs

- 单次成功不足以证明 Skill 产生收益 → 不确定与混杂写入观察；严格区分代码修复对照和 Harness 改动对照。
- 模型仍可能误判语义新颖性 → 保留人工审核，不把引用校验称为语义真值验证。
- 参照是有界的实际读取集合 → 只能保证模型看到了这些来源，不能承诺全库语义去重。
- 新增参照占用上下文 → 为参照留预算并对观察继续分批，不增加模型上下文上限。

## Migration Plan

无需 schema 变更。已有正式知识及候选保持原事实；新规则用于后续复盘。需要回退时恢复提示词与参照注入，不影响 Task/Worker 生命周期。
