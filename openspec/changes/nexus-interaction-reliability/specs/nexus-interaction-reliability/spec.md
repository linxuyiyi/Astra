## ADDED Requirements

### Requirement: 私聊接收结果明确
系统 MUST 明确拒绝正在处理中的额外私聊输入；客户端 MUST 显示原因并保留可重试内容，不把拒绝当作已接受。

#### Scenario: 忙碌时连续发送
- **WHEN** 同一私聊已有运行且又收到消息
- **THEN** 后续消息返回冲突，不进入员工历史，页面可见失败并可重试原内容

### Requirement: 交接回复可追溯
系统 SHALL 支持精确姓名、员工 ID 与唯一岗位联系；多义岗位 MUST 拒绝并给出候选。原生视图与发送方下一轮 SHALL 读取这条私聊对应的真实同事回复，保留来源身份。原始工具协议输出 MUST 标记不可用，不得当作已完成方案。

#### Scenario: 按岗位交接并追问
- **WHEN** A 联系唯一岗位的 B，B 完成答复，人类查看或追问
- **THEN** 人类和 A 都能读到来源明确的 B 答复，以投递标识关联回复，不因请求原文相同而选中其他私聊答复

#### Scenario: 岗位多义或协议输出
- **WHEN** 岗位对应多个员工或 B 仅产出原始工具协议
- **THEN** 系统报告明确错误，不猜选同事或展示虚假的成功答复

### Requirement: 群路由与预算可解释
系统 MUST 排除代码、引号、日志引用中的点名；有效单人点名只由目标回应。多员工讨论 SHALL 保留实际总 token 消耗，但用本次生成 token 限额控制继续发言，仍受时间、轮次、单次输出上限约束。追加同事与每个增量事件 SHALL 带讨论和员工来源。

#### Scenario: 分析日志
- **WHEN** 用户点名 A 分析含 B 点名字符串的日志或代码
- **THEN** 只有 A 被安排发言，不因引用内容或 A 的引用回答追加 B

#### Scenario: 三人长上下文
- **WHEN** A/B/C 已选中且生成、时间和轮次预算未耗尽
- **THEN** 完整输入历史的重复计量不阻止 C 发言，记录实际总消耗和完整参与者

### Requirement: 工具状态与任务能力真实
工具失败 MUST 显示失败，不汇总为成功编辑；任务能力 SHALL 提供启用分类和明确类型；无可信发起者的邮箱 MUST 不挂 Task MCP。

#### Scenario: 失败工具与邮箱
- **WHEN** 工具明确失败，或邮箱会话同步任务技能
- **THEN** 工具显示失败终态；邮箱不会装载无法授权的任务 MCP

#### Scenario: 发现分类并创建
- **WHEN** 有任务权限的员工查询分类并创建需求
- **THEN** 仅返回启用分类，工具类型限定 ISSUE 或 REQUIREMENT，标题前缀不作为类型
