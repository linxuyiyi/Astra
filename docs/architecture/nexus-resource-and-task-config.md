# 资源配置与分类派工

Skill 和 MCP 都是独立登记、独立绑定的资源。管理页只展示实际登记的资源；员工绑定哪个资源，就通过通用同步装入哪个资源。Skill 不自动安装 MCP，资源名称不触发特殊能力。保存员工后，以全部目标会话的最终同步结果更新页面状态。

## Task MCP

Task MCP 是独立的内网服务，登记到 MCP 管理并绑定员工后使用。创建任务传入责任数字员工的 `employee_id`，仅检查该员工是否存在，不校验用户身份、员工岗位、Skill 或来源会话权限。

```json
{
  "employee_id": "员工编号",
  "task_type": "REQUIREMENT",
  "category_id": "任务分类编号",
  "title": "开发产品版本查询 MCP",
  "description": "提供产品版本查询能力",
  "acceptance_criteria": ["查询接口正常返回版本列表"]
}
```

任务没有仓库 ID，不查询仓库列表。`source_session_id`、`source_conversation_id`、`source_channel_id` 是可选的通知回传信息，不用于权限判断；未提供来源会话时，现有唤醒机制将通知发送到责任员工邮箱。查询和后续控制使用任务 ID，继续沿用任务状态、当前执行会话和请求/回合有效性规则。

## Agent Worker

Worker 直接配置支持的任务分类、任务类型、Git 地址、目标分支和工作目录。访问令牌可选，直接加密保存在该 Worker 的执行环境中，API 只返回是否配置，不返回令牌内容。无需先登记或绑定独立仓库对象。

任务按分类和类型派给可运行且空闲的 Worker；不比较任务仓库与 Worker 仓库，也不校验 Git 地址与分类是否一致。代码部署和更新使用 Worker 自己的 Git 配置。

## 空库初始化

当前版本面向全新空库，使用单个 `0001_init` 创建当前结构。不提供旧库升级、历史配置转换、数据回填或双写逻辑。Nexus 自有业务表使用同一数据库；AgentScope 的独立数据库继续由官方 2.0.10 维护。
