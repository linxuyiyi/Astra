# 发送后输入内容残留修复

日期：2026-10-28（北京时间）；分支 `v1.4.8`。本次为明确的输入框生命周期缺陷修复，不改变发送受理、失败保留草稿或任务业务契约。

## 原因

私聊首次发送时，服务端返回新建立的执行会话绑定。前端更新绑定后重新加载历史，`ChatContent` 在 `loading` 时卸载了输入框。原输入框的异步发送随后返回成功，但清空动作作用于已卸载实例；新输入框从会话存储恢复尚未清掉的旧草稿，于是消息已经出现在上方，等待回复时输入框仍保留同一内容。

旧源码已在浏览器实际复现，截图 `before.png`：上方已发送气泡与输入框内容相同，同时显示“停止生成”。`before-state.json` 记录可控接口已受理且回复仍在进行。没有把公司线上日志或接口时序作为已验证事实。

## 修改

只修改 `services/nexus-api/chat-island/src/components/chat/ChatContent.tsx`：

- 加载期间保留输入框组件实例，避免会话绑定或历史重载导致草稿被重新恢复。
- 加载期间禁用输入框，避免向尚未准备好的会话发送。
- 沿用现有“受理成功后清空、失败保留、另写的新草稿不清空”的逻辑，没有改成点击发送就丢弃草稿。

差异中的主体缩进变化来自移除条件包裹；忽略空白后只有上述生命周期和禁用条件的改动。

## 验证

实际浏览器加载当前聊天岛源码，使用独立 Vite 18846 和本目录 `fixture_server.py`（仅绑定回环地址 18845）模拟消息受理、首次绑定、延迟历史读取、持续回复及 409 拒绝。无真实员工/模型调用，不接触公司服务。

1. **旧行为反例**：首条消息被受理后，输入框残留原文，且正在等待回复。
2. **修复后的首次消息**：绑定更新、历史重载后，已发送气泡保留，输入框为空，显示“停止生成”。见 `after-waiting.png`。
3. **刷新**：回复仍进行时刷新，历史消息仍可见，输入框保持为空，旧草稿未恢复。
4. **拒绝发送**：接口返回 409，页面明确提示失败，原文仍在输入框，失败的乐观气泡移除。见 `rejected-draft-kept.png`。
5. **新草稿保护**：已有会话的发送请求延迟 8 秒；返回前将输入改为下一条草稿，受理后新草稿保持不变。见 `new-draft-kept.png` 及 `after-state.json`。
