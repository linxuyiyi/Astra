# UI 清理复验遗留处理

本轮基线：`b28dd5ebd`（包含前轮 `55e21fbf6` 和远端新增的 Worker SSH 部署提交）。继续复用 `codex/ui-coherence-copy` 工作区，原始目录不变。

## 原因与修正

用户复验指出的三处遗漏均属实：

1. E66 只删了标题的 FieldHelp，同一说明还在节点额度卡正文中重复显示。本轮删除该 `<p>`，保留额度策略、小时/每日限额、已用量和未知用量请求数。
2. 任务创建描述的占位符仍是教学句。本轮缩为“任务描述”。
3. 任务详情仍有未使用的 FieldHelp 导入。本轮删除。

前轮“E1–E82 已处理”的表述覆盖过宽：E66 在 `55e21fbf6` 中确实有遗留，以本轮修正及页面证据为准。

## 长度与头像项目的处理边界

| 项目 | 当前结论 |
| --- | --- |
| C5 员工职责/指令 | 保留完整编辑与显示高度保护；API 没有 max_length，本轮不新增硬限制 |
| C6 任务描述 | 标题/标准已有上限，描述仍不限长；不宣称超大输入风险已解决 |
| C7 环境说明/工作路径/仓库 URL | 前轮已有部分字段限制与摘要换行；报告指出的其他字段仍没有前端硬上限 |
| C8 MCP/分类 Prompt/Skill/资源正文 | 保留大文本编辑与滚动；本轮没有增加软限制或硬限制 |
| C14 知识正文 | 摘要已有 4000 上限；普通编辑与候选审核的正文均没有 API 长度上限，维持一致 |
| C11 头像裁切 | 保留有意设计。固定角色素材为 256×320；前轮浏览器已验证 9 张均可解码。本轮未改头像，也未重新执行该项验证 |

以上长度项只完成了布局保护，输入体积的端到端限制仍是剩余风险，不能按“全部已有 maxlength”验收。若后续引入业务长度/请求体积上限，需要先定义字段语义、超限处理及前后端一致性，按仓库行为契约流程实施。
