## ADDED Requirements

### Requirement: 移除解释性页头与机制说明

页面 SHALL 移除标题下方解释内部实现或教学性质的副标题，以及聊天界面的“只有一条私聊”“不会代写同事回复”等机制说明。

#### Scenario: 页面标题区
- **WHEN** 用户进入任务大厅、Worker、图书馆、配置中心或网关页面
- **THEN** 标题下不显示解释性副标题，页面主要操作与内容保持原位

#### Scenario: 必要提示保留
- **WHEN** 页面出现加载失败、校验错误、权限不足、限流、人工确认或部署/重启进度
- **THEN** 这些提示仍然完整可见，不被文案清理移除

#### Scenario: 空状态保留
- **WHEN** 列表没有数据
- **THEN** 仍显示“暂无任务”“暂无群组”等简短空状态

### Requirement: 工具结果与人类可见消息分离

`contact_employee` 的执行结果 SHALL 继续返回给 Agent 用于推理；聊天界面 MUST 只把“已联系 XX”“联系失败：原因”等结构化状态作为轻量工具状态展示，不把工具长文本原样当作人类消息。

#### Scenario: 联系成功
- **WHEN** 数字员工成功联系另一位员工
- **THEN** 聊天显示“已联系 XX”的轻量状态，不显示“对方正在分析/已经回复”等未证实状态

#### Scenario: 联系失败
- **WHEN** 联系目标不存在或投递失败
- **THEN** 聊天显示“联系失败：原因”

#### Scenario: 对方真实回复
- **WHEN** 被联系的员工随后产生回复
- **THEN** 回复以该员工身份单独进入消息流，不由发起方代写

### Requirement: 不删除真实业务内容

文案精简 MUST NOT 无差别过滤模型回复、错误原因、字段级帮助或群组目标等业务数据。

#### Scenario: 模型真实答复
- **WHEN** 数字员工返回业务答复
- **THEN** 答复内容完整展示

#### Scenario: 字段帮助
- **WHEN** 用户需要理解表单字段含义
- **THEN** 字段级帮助仍可通过相邻提示或 tooltip 获取
