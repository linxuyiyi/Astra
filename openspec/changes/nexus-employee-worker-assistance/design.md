## Context

Task → RuntimeSession → Worker 原生 Session 是执行绑定；Task 的 responsible_employee_id 与 source_session_id 标识责任员工及来源聊天。原生提问、ACP 审批与 Worker 输出仍以运行时为准，AgentScope 保存聊天和员工推理上下文。

## Goals / Non-Goals

实现员工先处理求助、必要时向原对话的人求助、再向同一 Worker 回传。保留原任务验收。不开新 Agent、不做服务端答案生成或关键词判断、不复制原生请求状态。

## Decisions

- Task MCP 增加求助查询、原生回复和文本续答工具；查询实时请求，回答必须携带当前绑定 ID 和请求 ID；DSH 文本续答再校验当前提交标识。复用 RuntimeService、DshLifecycle 和 Worker 通道，拒绝 HTTP 自调用和第二套状态机。
- WAITING 提示要求员工先查询任务及求助详情；任务技能决定自动答复或向人提问。DSH 没有业务提问协议时，让 Worker 在正常回合输出明确问题，由员工读取持久执行轨迹 后通过同一 Session 续答，不声称已登记不存在的 Task MCP。
- 群任务的 WAITING 事件在原群排入新讨论，仅唤醒责任员工；发起身份取原任务审计记录，重新检查有效成员，不恢复旧讨论的权限。普通群聊不自动触发模型。
- 每次写入先锁定并重读 Task/绑定，检查来源、当前轮和取消栅栏。原生请求消费保证同一请求不能再次使用；网络异常不声称成功，也不盲目重发。
- 不保留已接受的聊天副本；审计只记录员工、请求标识和操作类型，不记录回答正文。
- 查询不跨网络持有 Task 行锁；发送原生回复前再次核对绑定与执行栅栏，仅在发送至受理期间持锁，以串行化停止/切换。DSH 文本续答沿用既有提交时的原子比较与交换，并补充来源及回合校验。
- 复用 Event 记录最近通知过的原生请求标识；连续 WAITING 的新请求也生成发件箱记录，同一请求重查不重复唤醒。该记录只用于通知去重，不决定请求是否仍有效。
- 私聊唤醒前重新挂接任务能力；版本请求头使已有 MCP 配置重新装入工具结构定义。挂接失败返回 503 保持发件箱重试。群聊在新讨论内沿用正常能力挂接，内部工具提示不放到公开群消息中。

- OpenCode 输出复用现有原生消息分页读取和原生轨迹归一化逻辑，排除用户提示，提供脱敏回复与工具输出摘要及退出码；不持久化第二套执行历史。员工按分页游标 `next_cursor` 读取并说明摘要局限。

## Risks / Trade-offs

- 模型判断是否需要人仍依赖上下文和模型能力 → 技能明确已知事实、不得编造授权、模糊答复必须澄清；真实模型验收单独记录。
- 原生审批可能超时 → 员工必须重查，过期回答拒绝；不改 Worker 超时策略。
- 不同进程无法在单次数据库事务中原子提交原生回复 → 依靠原生请求 ID、绑定校验和取消栅栏，并对受理回执不明返回失败。
- 原生已确认受理后审计或刷新失败 → 返回 accepted=true、refresh_required=true，避免把已受理回复误报为失败后重发。发送期间丢失受理回执 则不声称成功。
- 部署需要重启 Task MCP/服务并向已有 AgentScope Session 更新任务技能；不修改数据库结构。
