## Context

Worker 路由已有自己的协议鉴权。统一认证中间件却先要求浏览器 Cookie。维护接口原属可信代理/手动 UID 模式，与 Nexus 服务端账号不一致。

## Goals / Non-Goals

验证真实执行与数字经验闭环，修复有证据的集成阻断。不绕过 Worker 健康与版本门禁、不新增执行编排、不修改 AgentScope 内部存储。

## Decisions

- Worker 路由交由原协议依赖校验；端到端覆盖真实登记、数据拉取及错误凭据，防止放宽权限。
- 在统一服务组合根绑定维护身份依赖到 Nexus 登录账号；独立 app 的旧部署契约不变，不在业务处理器里叠加身份猜测。
- 同样适配知识审核和执行停止确认身份。任务详情使用既有占用谓词导出的 `execution_released`，人工明确核实后调用既有停止确认接口。
- 任务状态、Worker 占用和 OpenCode Session 分别读现有事实源；复盘仅由人工确认触发，候选保持人工审核后发布。
- Task MCP 仓库来自现有 CodeRepository；指定 Worker 省略目标时只使用该环境绑定。创建/改派校验一致性，派生幂等键包含仓库，不创建空目标。
- OpenCode 的 synthetic 上下文仍隐藏于原生页面，但不设置会让模型忽略它的 ignored 标记。工具继续校验真实 Session 绑定；复盘归一化先脱敏，候选再执行凭证校验。
- Worker 复盘复用工作区路径校验；根目录旁的任务路径还必须属于同一 Git 仓库且已注册，拒绝任意兄弟目录和符号链接。
- 成功完成复盘时清除旧错误，新增证据写入 review_job_id。旧记录只通过显式 Job 的一次性修复脚本处理，不增加长期兼容判断。
- Wiki 读取仅按 YAML 元数据与已发布 source_path 归因；多来源、正文示例或未知来源保留读取事实，避免虚构关联。
- 图书馆来源和使用记录的现有外键指向 AgentWorker，页面据实标为来源/执行 Worker；责任数字员工仍从来源 Task 追溯，不改写成另一种身份或个人记忆。
- Linux QA 单独进程、Git 工作区、Redis 和数据库；使用真实网关，不触碰原 Worker 与主库。实际 Wiki 项目中的 QA 来源单独标识。

## Risks / Trade-offs

真实模型、外部 Wiki 和远程连接可能揭示额外问题，逐项记录。测试仓库只验证可重复的工程工作，不代表生产容量或任意模型的行为保证。发布与检索会使用明确标识的 QA 经验。
